# v0.2.0 - Reproducible CPU inference and quality evaluation

Released 2026-09-08. This research release includes the work from PRs #1, #2 and #3,
plus a reorganized public documentation set. Source code is MIT licensed; model weights
are downloaded separately and retain their upstream licenses.

## Changes

- Correct HF token/cache alignment, including pending EOS, reset and context limits.
- Full-history API chat, independent anonymous requests and text streaming during decoding.
- Removal of unused static KV allocations from the live HF engine.
- Repeated benchmark trials, correct prompt-length labels, separate timing definitions,
  hardware/dependency metadata and sampled process memory.
- Pinned Qwen HF/GGUF artifacts and runtime, checksums and prompt-token parity validation.
- Real retrieval, absent-record, cached/fresh conversation and paired explicit-ID experiments.
- Documentation index, setup guide, API/migration contract, architecture and next-PR roadmap.

## Results and validation

23 download-free tests passed before release. Real-model experiments and a production GGUF
stream/reset smoke check are documented in [the results](../experiments/results/README.md).

The three-seed control found initial retrieval correct 3/3, implicit follow-ups 0/3,
explicit-ID follow-ups 3/3 and absent-record controls 0/3. All 12 cases used fresh KV state.
At 2,030 prompt tokens, GGUF Q4_K_M decoded faster and used less sampled RAM than HF FP32,
while HF had lower first-token latency. Runtime and precision both differ.

These are small synthetic studies on one host. They do not establish general reliability,
CPU-over-GPU superiority, 32K/50K quality or production readiness. Static cache and attention
kernels remain separate experiments. The missing-record failures are unresolved.

## Compatibility

API clients using a session ID must send the complete message history. Anonymous requests
are independent. Handle null metrics, particularly GGUF serving usage/TPOT and single-token
HF TPOT. Benchmark prefill keys are `prefill_full_s` / `prefill_chunked_s`. See [migration](../api.md).
